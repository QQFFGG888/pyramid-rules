# 自检清单

覆盖金字塔专项、十条规则与去 AI 感校验。产出后逐条核对，把计数汇报给用户作为达标证据。任一项不过就改到通过为止，未通过前不交付。

机械项由 scripts/selfcheck.sh 检查，运行它得到 PASS/FAIL 计数。本文件保留全部检查项，并写明无法写成脚本的人工项怎么判读，如小白复读、不引入新词解释旧词、比喻一致、要素完整、因果链、自然引导、先讲前置概念与用词通俗。

适用范围：脚本与清单用于教程产出文件。SKILL.md、references 与 README 属规则文档，条文必须点名禁词，对这些文件跑脚本会产生固定误报，判读时逐行确认命中是否为条文引用。

## 金字塔专项 6 项

### 1 L1 零术语

规划阶段已生成术语黑名单，L1 禁止出现其中的正式术语。只对每章「生活场景」节文本 grep 黑名单，「中文词（英文——解释）」形式除外。

```bash
for k in "术语1" "术语2"; do
  c=$(sed -n '/生活场景/,/^### /p' 产出文件.md | grep -c -- "$k")
  [ "$c" -ne 0 ] && echo "L1 出现术语: $k"
done
```

「中文词（英文——解释）」形式可先按 `grep -v "（[A-Za-z]"` 过滤再计数，或逐处人工确认格式正确。

### 2 小白复读测试

只读全部 L1 节，回答两个问题：像什么？解决什么麻烦？答不出即 L1 失败，重写这一段，不要打补丁。

### 3 不引入新词解释旧词

检查每个定义句，定义中出现的词是否都是已解释过的词或 L2 表中的术语。发现「用新词解释旧词」即改写。

### 4 比喻一致

全文 grep 比喻关键词，含选定系统的意象词与常见竞争意象词。第二比喻系统的意象出现即违规。

```bash
grep -c "第二比喻意象词1\|意象词2" 产出文件.md   # 期望 0
```

### 5 要素完整性

逐概念核对五要素，是什么、为什么需要、解决什么、怎么运作、何时不用，至少 5 项齐备。缺项时要么补，要么在「常见困惑」声明本篇不覆盖。

### 6 因果链完整

抽查每个「所以 / 因此 / 这意味着」，往前能否找到对应的「因为 / 由于」。找不到即补推理或删结论。

## 规则校验

### 规则 1 内容自包含

逐个前置概念检查，首次使用处有一句话定义或可回指。全文不得出现没有着落的引用，例如写「如前所述」但前文没讲过。

### 规则 2 纯交付物

```bash
grep -c "修订说明\|版本说明\|改动对比\|修改前\|修改后\|本次更新\|本次修订" 产出文件.md   # 期望 0
```

文首元信息里的「版本号：v1」属规则内，不算修订说明。

### 规则 3 自然引导

逐个正式术语检查，首次出现位置之前正文已有其对应的生活场景或动机句。出现「先给定义再解释」的倒置即调整顺序。

### 规则 4 章末检验

```bash
grep -c "^\*\*章末自检\*\*" 产出文件.md   # 应等于概念章数
grep -c "^- \[ \]" 产出文件.md            # 章末不得用勾选框，仅前置准备块允许
```

### 规则 5 语言简洁

抽查三类复杂句：多重从句、三点以上并列长句、一句塞两个以上事实。发现即拆短句。

### 规则 6 富文本辅助

逐个代码块、截图、流程图检查，正文有引出或说明且服务于理解。纯装饰性插入即删除。

### 规则 7 符号规范

```bash
# 冒号后长内容未另起一行，同一行内冒号后达到 30 字符即嫌疑，逐处人工确认
grep -n "：[^ ]\{30,\}" 产出文件.md
```

### 规则 8 标题规范

```bash
grep -c "^## [0-9]" 产出文件.md     # 应等于 H2 总数，编号无遗漏
grep -c "^##### " 产出文件.md       # 期望 0，最多三级编号
```

标题文本逐条人工过一遍，不罗列主题对象、不重复正文信息、用短语，不要写成长句。

### 规则 9 开头格式

文首六要素按序齐全，教程名称、版本号、撰写者、总字数、预计阅读时间、主题简述。总字数与实际统计一致，阅读时间按字数除以每分钟 400 字向上取整。

### 规则 10 去 AI 感润色

```bash
grep -c "总的来说\|不难发现\|值得注意的是\|综上所述\|不仅仅是\|让我们一起\|某种意义上" 产出文件.md   # 期望 0
grep -c "！" 产出文件.md          # 期望 0
grep -c "……\|～" 产出文件.md      # 期望 0
```

连续排比与连续等长句做人工抽查，发现即打散。

双音节词做单音节化抽查：通读全文，找被压成拗口单音节词之处，如「可作」「建直觉」「落名字」。发现即恢复为通顺双音节词，如「可作为」「建立直觉」「知晓名词」。

## 结构项 四段顺序与术语编号

逐章人工核对。

- 原文段如有，先于其解释出现，中途未被别的内容隔开。原文较长时按段拆开，每段各自配解释，整组的精读段放在最后。
- 精读段在浅读段之前，先出技术解释，再用通俗解释落回读者语言。
- 术语首现处均带编号，全篇连续，不重不漏。
- 章末「本章名词」行与文末速查表编号一一对应，无缺号、无跳号。
- 正文不出现段名标签。

## 写法项 先讲前置概念与用词通俗

逐项人工核对，这两项不进脚本。

- **先讲前置概念**：逐个概念核对，讲解中引用的术语，其所属概念是否都排在它前面并已讲完。出现引用后置概念，或用「先给一句话定义、后文再细讲」的方式提前使用后面的术语，即违规。核查到前置不足时，正确的做法是重排概念顺序，不是补一句定义。原文段不受此项限制。
- **用词通俗**：抽查正文里的抽象词与自造词，把词单独拎出来给一个高中生看，要多想一步才明白即换掉。对照本 SKILL 自己的用词标准：不自造压缩词，不借其他领域的专业词，不生造比喻式命名。

## 通用 grep

```bash
# 禁词，来自用户当次指定
grep -ci "禁词A\|禁词B" 产出文件.md        # 期望 0
# 写作过程的话
grep -c "接下来\|下面将\|本文将\|值得注意\|我们要\|首先说明" 产出文件.md   # 期望 0
# 破折号，术语格式内的除外
grep -c "——" 产出文件.md
# 结构，概念章数应等于章末自检数
grep -c "^## " 产出文件.md
grep -c "^\*\*章末自检\*\*" 产出文件.md
```
